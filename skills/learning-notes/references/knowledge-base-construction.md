# 整套知识库的构建方法

本页用于把一份手册、一组源码、一个专题资料集或已有零散笔记整理成可长期阅读的完整知识库。目标不是尽量多地产生文件，而是让读者知道先学什么、知识怎样连接、遇到问题去哪里，以及哪些内容只是项目中的具体采用方式。

## 先定义读者要走完的路径

开始建目录前，先写清三件事：读者是谁、学完要能判断什么、资料的事实基线是什么。随后用一条因果主线组织内容。例如卷绕控制可以是：

```text
卷绕物理
→ 张力控制模式
→ 卷径估算
→ 转矩前馈
→ 闭环修正
→ 锥度目标
→ 驱动接口
→ 调试与诊断
```

PID 可以是：建立反馈直觉 → 理解 P/I/D → 离散化 → 工程问题链 → 源码实现 → 对象建模与整定 → 高级结构 → 应用。目录服务于这条理解路径，不能只是照抄手册章节。

## 入口层只负责建立方向

规模较大的专题通常需要一个精简入口层，可按实际需要选择：

- 总入口：说明知识库范围、来源基线和最佳起点；
- 知识地图：用一张关系图说明几条主线怎样连接；
- 学习路线：按读者基础给出有目的的阅读顺序；
- 资料映射：说明原手册章节或源码模块在知识库中的去向；
- 符号与单位：统一公式、方向、标幺值和量纲；
- 现场或复习速查：从现象进入原因与下一步检查。

入口页只带路。它可以说明每个入口解决什么问题，但不复制各章完整摘要、公式推导和参数表。若一份“总汇 Markdown”只是把全部文件串接在一起，应把它视为派生的便携阅读物，不作为继续维护的第二份正文源。

## 正文按知识职责分层

下面是可复用的职责顺序，不是必须照搬的目录模板：

| 层次 | 回答的问题 | 典型内容 |
| --- | --- | --- |
| 基础与直觉 | 系统为什么这样工作 | 物理关系、反馈直觉、术语 |
| 模式与机制 | 有哪些方案，各自为何成立 | 控制模式、状态变化、因果链 |
| 算法与公式 | 输入怎样变成结果 | 推导、单位、数字算例、误差来源 |
| 实现与接口 | 思想怎样落入程序或设备 | 状态、功能块、关键参数、调用关系 |
| 配置与诊断 | 怎样采用，出错先看什么 | 生效条件、中间量、限幅、诊断树 |
| 项目映射 | 当前项目怎样采用通用知识 | 取舍、差异、接口位置、待验证项 |
| 附录与速查 | 怎样快速找答案 | 术语、公式、功能索引、现场卡片 |

通用原理只维护一份。项目映射页说明“本项目怎样采用、哪里不同”，不能复制整套通用教程；现场页从症状进入诊断，不重新讲一遍全部理论。

## 先用代表页校准，再批量展开

不要先生成上百个标题相似的短页。先选择能暴露写作难度的代表页：一个基础概念、一个公式算法、一个实现接口、一个诊断问题和一个项目映射。确认它们已经讲清直觉、机制、例子和边界，再沿相同质量展开其他主题。

页面围绕一个可独立回答的问题拆分。内容短但问题完整可以保留；只有几句定义、固定元数据和“作用是提高稳定性”的页面应合并或补写。文件数、平均篇幅和目录层级只能帮助发现异常，不能代替阅读质量判断。

每页可按主题自然选择以下材料，不要求机械套满：

- 一句可判断的结论或读者现象；
- 工作机制或因果链；
- 带条件、数字和单位的例子；
- 参数或接口为什么存在；
- 成立条件、失效方式和常见误解；
- 与前置知识、后续应用或项目采用方式的关系。

“类型、主要依据、定位”只在它们真的帮助判断来源或适用范围时出现。不要给每页复制完全相同的三行元数据；来源页或章节入口能统一说明的内容，不在所有正文重复。

## 从资料生成整库的顺序

1. 盘点输入材料，区分原始资料、既有解释、项目事实和未经确认的推断。
2. 提取核心对象、变量、公式、状态、接口、故障现象和相互关系。
3. 画知识地图与读者路线，再设计页面职责和目录，不按素材顺序机械拆页。
4. 写代表页，核对术语、单位、示例深度和项目边界。
5. 批量展开正文，同时合并重复问题，避免同一解释在多个章节出现。
6. 补入口、资料映射、术语、公式速查和必要的现场诊断入口。
7. 检查跨页引用、相对路径、标题、公式符号和项目映射是否一致。
8. 最后才生成清单、manifest、总汇文件或 ZIP，并把它们标为派生产物。

材料间结论冲突时先核对版本、条件、单位和对象，不把多数表述当成真相。手册能证明产品接口，通用公式能解释机制，项目源码能证明当前实现；三者不能互相冒充。

## 压缩包与可导入目录

用户要求直接生成压缩包时，包内使用一个明确的根目录，包含入口 README、分层正文和必要来源说明。文件名使用稳定、可读的 UTF-8 名称；排序前缀只用于文档树，不写进正文标题。

可选 manifest 记录名称、版本、来源基线、内容范围和正文数量，但不能宣称内容正确。源码或计算脚本只在帮助理解时附带，并注明它是学习辅助，不自动升级为需要编译、测试矩阵和持续集成的软件项目。

如果目标是导入思源，先搜索现有主题和主入口，再决定新增、融合或作为项目映射保留。ZIP 完整不等于思源导入完成；只有实际写入并读回后，才能报告内容或结构已经进入工作区。

## 轻量验收

整库完成前至少检查：

- 根入口、学习路线和正文路径存在；
- Markdown 文件非空，没有只有模板头的占位页；
- 导航链接和相对路径可达；
- 同一概念、符号、单位和方向约定一致；
- 代表性的原理页、算法页、实现页、诊断页和项目映射页达到相同深度；
- 没有把导航、总汇或版本说明变成第二份正文；
- manifest 中的数量与实际可维护正文口径一致；
- 压缩包可列出并解压到单一根目录。

学习知识库默认不需要编译代码、连接设备、建立测试矩阵或做硬件验收。只有用户要求验证随附程序或真实项目行为时，才进入相应工程流程，并把知识内容、代码运行和现场采用分别报告。
