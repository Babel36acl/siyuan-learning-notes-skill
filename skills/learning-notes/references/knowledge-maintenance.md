# 知识库长期维护

当笔记从“刚开始积累”进入“页面很多、多人或多次维护”的阶段，问题就不再只是怎样写一篇好笔记，还包括每条知识归哪里、谁负责更新，以及以后从哪里找到。

## 先判断生命周期

知识通常经过：

采集 → 理解 → 稳定入口 → 项目应用 → 复盘 → 合并或归档。

新建前先问：这是已有主题的补充，还是一个真正独立的问题？维护旧页时检查它是否仍承担原来的职责。发现重复入口时，保留一个主解释页；其他页面根据用途改为导航、项目应用、操作或历史页。不要只因为新页面写得更完整，就把旧页面当成废页。

## 笔记本按生命周期划分

笔记本边界优先依据以下四项，而不是主题名称是否相似：

- 生命周期是否一致；
- 更新责任是否一致；
- 主要阅读对象是否一致；
- 归档和淘汰方式是否一致。

例如，脱离项目仍成立的原理和代码模式适合长期工程知识；一个产品的参数、接口和现场问题属于项目库；工具源码和发布资料属于工具项目；当天产生的零散信息先进入日报，整理后再归位。标签用于跨目录检索，不能掩盖生命周期混杂。

## 导航页只负责带路

导航页回答“先看什么、遇到什么问题去哪里、每个入口负责什么”。它不复制完整教程、参数表或项目正文。导航开始解释一个主题的全部因果关系时，应把解释放回原理主笔记。

## 项目页与通用页分工

通用页解释原理、因果、例子和边界；项目页说明本项目如何采用、作了什么取舍、当前接口在哪里；操作页提供完成目标所需的步骤和速查信息；复盘页记录现象、原因和改进。项目页引用通用页，不整段复制通用教程。

持续维护的项目通常至少需要：项目总览、架构与职责、运行流程、控制与算法、接口与参数、问题复盘、验证与现场、快速接手。不是每个项目都要新建完整目录，已有页面能承担职责时直接补充。

## 拆分、合并与脱敏

页面包含多个独立问题、不同读者、不同更新频率或不同生命周期时考虑拆分。仅仅因为页面变长，不必立即拆分；大型专题可以有子目录。

从源码或项目中发现可复用的代码结构时，先去掉项目名、设备名、路径、内部变量和机密，再按“语言 → 模式”放入代码模式库。一篇笔记围绕一个可复用思想，不要一段代码建一篇孤立笔记。原项目页只说明采用了哪种模式。

## 每轮维护的最小检查

先搜索主题和已有入口，再修改当前受影响的正文、导航或归属。完成后检查：是否只剩一个主解释入口、旧状态描述是否仍准确、导航是否复制正文、标签和引用是否各司其职，以及新文档是否有合适图标。不要把工具调用过程、事务复核记录或尚未证实的推断写成普通学习正文。
