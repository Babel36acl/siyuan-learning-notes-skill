# 思源知识组织与工具使用规范

目标是让笔记容易理解、找到、关联、复用和更新。目录、标签、引用、数据库各自承担一种明确职责；充分使用适合当前任务的能力，不以使用工具数量作为完成标准。

用户只要求创建规范、Skill 或 AI 指导时，只创建这些交付物。盘点得到的重复页、断链和分类问题用于改进规则，不自动转成对现有笔记的重写、迁移、合并、删除或批量打标签。

## 1. 分区职责：一个内容只维护一份主笔记

先沿用现有笔记本和分区，按照“这页主要为读者解决什么问题”确定归属。以下是职责模型，不是每个知识库都要新增的目录树。

| 分区或页面类型 | 负责什么 | 不重复维护什么 |
| --- | --- | --- |
| 总导航与主题入口 | 最佳起点、阅读顺序、主题之间的关系 | 全文摘要、完整参数表、整套操作步骤 |
| 原理与概念 | 因果、推导、例子、适用边界 | 每个项目的实时配置与版本快照 |
| 项目应用 | 本项目怎样采用原理、作了什么取舍、当前接口 | 通用原理的完整重写 |
| 操作与速查 | 完成目标的步骤、地址/单位/参数、症状排查入口 | 长篇原理与分析流水账 |
| 经验与复盘 | 原来怎样误判、为何发生、以后如何判断 | 已由主笔记维护的当前算法或参数表 |
| 来源与历史 | 原始资料、版本条件、历史选择、待确认部分 | 伪装成现行结论的旧快照 |
| AI 与工具指导 | 写作原则、工具选用、维护流程 | 具体项目技术正文 |

“卷径怎么从位置求出”适合原理主笔记；“HC300 使用哪些反馈和窗口”适合项目应用；“参数在哪、什么单位”放速查；“以前为何误用 RPM”放复盘。后三者按需要引用前者，不能各复制一份完整推导。

一页横跨多个主题时，先看是否围绕同一问题共同解释；有完整主线就保留。只有各部分已经能独立阅读、也有独立复用价值时才拆分。主笔记根据解释完整性、已有引用、更新责任选定，不能简单以“最新页”取代其他页面。

知识库规模变大后，分库依据应优先看生命周期、更新责任、主要读者和归档方式。脱离项目仍成立的原理放长期知识库；产品实现和现场问题放项目库；工具源码与发布资料放工具项目；时间流信息先放日报，整理后再归位。标签只负责跨目录检索，不能替代生命周期边界。

## 2. 目录、标签、链接和关系图的分工

| 机制 | 回答的问题 | 使用规范 |
| --- | --- | --- |
| 文档树 | 这页主要归哪里 | 一处主归属；跨主题使用链接，不复制页面 |
| 大纲 | 这篇内部怎样展开 | 标题表达问题或结论；不要用空泛编号代替含义 |
| 标签 | 怎样跨目录找同类内容 | 少量稳定维度，复用既有词汇 |
| 真实块引用 | 这两段知识有什么关系 | 在自然句中说明前提、应用、对比、因果或反例 |
| 反向链接 | 哪些内容用到了它 | 复用概念与评估修改影响；不强制手写反向列表 |
| 局部/全局关系图 | 知识如何连成网络 | 检查相关主题的连接与孤立页；不追求节点多、线密 |
| 书签 | 哪一段值得快速再看 | 用于少量重要块，不承担全库分类 |

真实引用形成可查询的关系。Mermaid 是解释图，不会替代思源引用；同标签也不等于两页存在前提或因果关系。若当前 MCP 不提供打开关系图的操作，完成真实引用并验证反链即可，把图谱显示留给客户端；不能声称已经打开或配置关系图。

引用目标优先选择具体概念标题或段落；只需整篇入口时再引用文档。稳定解释留在目标块，应用页保留自己的上下文。双链并不要求两个页面互相补一条相反链接：一条真实引用已经可以被反链发现，只有反向说明本身有意义才另写。

通过 MCP 写引用前查真实 ID，不能靠标题猜 ID。固定的语义锚文本可用 `((真实ID "位置增量与卷径"))`；希望名称跟随定义块变化时，按当前思源格式使用动态锚文本 `((真实ID '当前标题'))`，并读回确认。将“前提是”“应用于”等关系词写在引用外的自然句中。编辑器里 `[[` 可能是文档搜索入口，不能因此把 Obsidian 的 `[[标题]]` 原样当作 API 的持久块引用。

## 3. 标签规范：跨目录聚合，不再造一套目录

先用 `tag.list` 看当前词汇。优先复用；确实需要统一体系时，建议按用途选择以下维度，不要求每页全填：

- `#主题/控制算法#`、`#主题/工业通信#`、`#主题/知识管理#`：知识领域。
- `#类型/学习笔记#`、`#类型/速查#`、`#类型/复盘#`、`#类型/指导#`：读者用途。
- `#项目/HC300#`：有明确项目归属时使用。

同义概念只选一个常用标签；不能并列堆“卷径、卷径算法、收卷卷径”只为增加命中。`#工程知识#` 等泛标签通常无法区分内容，不给每篇堆上所有上位词。状态若需要持续流转，优先使用 AV 的状态字段；只做少量阅读筛选时才用状态标签，避免两处维护不同状态。

真实思源标签用成对的 `#`，层级用 `/`。放在可索引的正文块，不在代码块里假装打标；代码中的语法演示不算实际标签。写入后用 `tag.list(query=...)` 与目标块读回核对。标签是块级信息，需要聚合文档时按 root 文档去重；不能把同一页多处标签当成多篇笔记。

## 4. 按任务选工具

下表以编写时发现的 Sisyphus 工具为主要路线；官方 MCP 候选能力及连接边界见 [siyuan-mcp.md](siyuan-mcp.md)。用到某项时读取当次 action help，而不是盲用历史参数。

| 任务 | 工具路线 | 应得到什么 | 不这样做 |
| --- | --- | --- | --- |
| 确定笔记位置 | `notebook.list`、`fs.ls/tree`、`document.lookup` | 明确笔记本、父页、真实 ID | 全库遍历代替主题定位 |
| 查重复与知识关系 | `fs.search`、`search.fulltext/semantic` | 候选主笔记与相关段落，随后读正文确认 | 搜到相似词就宣布重复 |
| 浏览长文与大纲 | `fs.read`、`document.get_outline`、`block.get_children` | 完整窗口、标题和具体块 | 把截断结果当全文 |
| 新建/改写普通正文 | `fs.write/replace` | 可编辑的正文，位置正确 | 用一张截图承载全文 |
| 精确块与原生结构 | `block.get_kramdown/insert/append/update` | 正确块树与稳定引用 | 更新一个块时塞入多个兄弟块；覆盖复杂整页 |
| 引用与反链 | 写真实引用；`search.get_backlinks/search_refs` | 正向引用和可发现的入链 | 普通 URL、虚拟引用或 Mermaid 冒充双链 |
| 标签与书签 | `tag.list`；正文标签；`block.get_attrs/set_attrs` 的 bookmark | 分类与快速访问各就其位 | 把书签属性当行内标签 |
| 元数据、图标 | `document.set_attr`、`block.set_attrs` | 图标、名称、别名或必要 custom 属性 | 把内部元数据表堆在学习正文开头 |
| 多处显示同一内容 | 内容块引用；需要原位展开时用原生查询嵌入 | 复用主块而非产生副本 | 每次复制一份全文 |
| 自动汇总 | 受限 SELECT 查询、原生 query_embed | 按已验证范围更新的结果 | 写无限范围 SQL；结果包含汇总页自身 |
| 结构化资料管理 | `av.get/render/add_rows/set_cells` 等 | 真实 AV 容器、字段、行与视图 | Markdown 表格冒充数据库 |
| 图解与排版 | 普通块、提示块、超级块、Mermaid/ECharts 等 | 能减少理解负担的视觉结构 | 以装饰、动画数量代替内容 |
| 图片与附件 | `file.get_doc_assets/read_image/upload_asset` 等 | 可读资产、正确相对链接 | 将 OCR 缓存当作已看图；猜远程路径 |
| 可复用模板 | `file.list_templates/read_template/create_template/render` | 可预览、能实例化的原生模板 | “模板”标题的普通笔记冒充已注册模板 |
| 记忆与复习 | `flashcard.get_decks/create_card/get_cards/list_cards` | 由真实内容块注册的卡片 | 只写 custom-riff-decks 或高亮就声称已建卡 |
| 历史与恢复 | `timeline.list_nodes/create_node/compare_node`；必要导出 | 有明确范围的恢复点 | 每段都建快照；用局部历史冒充完整备份 |

本规范描述选用方法，不代表以上功能都已在用户工作区执行过测试。不需要为了展示能力新建 AV、模板、闪卡、资产、日记、自动化或权限规则。

## 5. 嵌入、数据库和模板怎样减少重复

短概念在语句中用块引用，读者可跳转或预览。确需在多个页面完整呈现同一段主内容时再使用原生嵌入，保留源块身份。查询嵌入使用已验证的 ID/标签/范围，通常排除当前 root，限制结果数并选择稳定排序；不要直接把用户输入拼成 SQL。

AV 用于“有字段、要筛选、要多视图”的集合，例如手册阅读状态、实验记录、待学主题。普通小比较用 Markdown 表格。面向已有笔记的资料库优先使用绑定行，以笔记块作为条目来源，不再复制一份标题和摘要。建议最小字段为“主题/类型/状态/来源链接”，只有明确检索需求再加字段；不同主题不强行共用一张巨表。

创建 AV 后确认文档里存在真实数据库块，读取行与字段；操作时区分数据库 ID、视图 ID、行 ID、列 ID、来源块 ID。表格、画廊和看板只是同一数据的不同视图，不能各维护一份数据。relation/rollup 只用于真实结构关系，不能替代正文中的知识解释。

模板保存稳定的提问顺序和必要字段，未填部分在成稿中删除。教程、原理、复盘可以不同模板；不要把具体项目路径、版本、人物、凭据或旧结论作为默认值。需要注册到思源时使用模板工具并先预览；用户只要模板笔记就交付笔记，不自动注册。

## 6. 闪卡、资产和历史的边界

闪卡适合可明确回答的概念、预测和区分题。先完成笔记解释，再选择少量内容块；不要把整篇文章或源码索引变成卡片。创建后读取卡组确认注册。实际复习结果由人的回答决定，不能自动给自己打分；专用复习 App 成功打开后，按 App 的交互与交接规则交还用户。

附件用于无法由文字/原生图表达的材料；同一资产尽量复用。上传前确认来源、文件所在机器与目标文档，保持资产路径由工具返回；引用检查或“未使用”扫描不是删除授权。交互 HTML 需要客户端实际执行验证，静态正文要保留核心解释。

涉及大幅改写或重组且已经获准时，先做有明确文档范围的快照或备份，再处理主笔记和引用迁移；不要默认全库重建。Markdown 导出不一定保存原生布局、AV、附件和历史，需要恢复这些对象时选择覆盖它们的备份方式。只生成规范时，不去运行快照、恢复、同步或迁移。

## 7. 写入与完成标准

普通创建、精准修改、原生结构编辑分别选择对应工具。严格写入按当次预检返回的凭据和 requestId 要求执行；修改已有内容前重新读取，遇到状态变化先停止本次写入并核对差异，不能以旧稿覆盖新内容。

验证只覆盖本次用到的能力：正文核对主要解释；双链核对真实目标与反链；标签核对索引；嵌入查看源块和渲染块；AV 核对容器、字段及行；模板核对预览；闪卡核对卡组；资产核对可读与引用。跨页操作确认没有产生第二份主笔记，已有独有内容与引用关系没有丢失。

没有打开界面时，把结果表述为内容/结构读回完成。没有调用工具时只说规范已写好，不说目录、关系图、标签、数据库或模板已经配置。
